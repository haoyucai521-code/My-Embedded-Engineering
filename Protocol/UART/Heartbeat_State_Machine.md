# 多板心跳机制与整机状态机（交接文档）

> 用途：给后续接手改造该板间心跳/运行态同步机制的 Agent/工程师的上下文。
> 范围：心跳承担的双职责、主控权威模型、发送策略、载荷设计、子板消费、电源生命周期联动。
> 约定：全文以"某多板 UART 总线系统"代称具体产品；以"主控 / 显示板 / 背板 / 侧滑板"称呼各板角色。
> 依据：本文与线上实现对齐（主控 `sendHb()`、`checkHeartbeatSend()`，各板 `ComProtocolPacketHandle` 的 HB 分支），改前先读实现再改文档。
> 姊妹篇：[板间 UART 协议可靠性设计要点](UART_Reliability_Design.md)（讲协议层的 ACK/重发/合并）。

---

## 一、心跳承担的两个职责

心跳帧（`CMD=HB`）在同一套协议里承担两件事：

| 职责 | 对应形态 | 做什么 |
|------|---------|--------|
| 状态机同步 | 形态2 | 主控把**运行模式**（关机/开机/工作/待机）广播给所有子板，子板各自维护本地副本 |
| 电源生命周期 | 形态3 | 关机/上电状态通过心跳传播，子板据此掉电自锁 / 上电开屏 |

关键点：**心跳不是"定期报个活"**。它是主控向全网广播"当前整机处于什么状态"的唯一下行通道，子板所有跟模式相关的行为都以它为准。

--- 

## 二、主控唯一权威模型

```
主控 MAIN（唯一权威）
  │  运行模式 POWER_ON / WORKING / IDLE / POWER_OFF
  │  周期 10s 心跳 + 状态变化立即补发
  ▼  广播 0xFF
显示板    背板
  │ 本地副本   │ 本地副本
  g_runningMode  g_runningState
```

- 主控是运行模式的**唯一权威**，子板不做任何推测，收到什么就是什么。
- 子板只维护**本地副本**（显示板 `g_runningMode`、背板 `g_runningState`），模式相关行为（显示板刷 LED、背板掉电判断）都读本地副本。
- 这是"广播不可靠"前提下状态能收敛的根本原因：**状态以主控为准，而不是靠子板之间的协商**。
- 代价：子板必须无条件信任心跳，所以心跳载荷的变化补发 + 周期兜底是硬性要求（见下节）。

## 三、发送策略：周期兜底 + 变化补发

```
checkHeartbeatSend():
  距上次心跳 ≥ 10s → 补发一次（周期兜底）

触发补发（变化即时传播）：
  运行模式切换（开机/待机/关机流程）
  旋转状态变化
  童锁状态变化
  关机命令下发前
  休眠唤醒后的状态同步
```

| 机制 | 作用 |
|------|------|
| 周期 10s 兜底 | 广播不 ACK，丢失一两拍靠周期包补上 |
| 变化立即补发 | 状态变更不等下一拍周期，即时传播 |

这是**广播不 ACK 能成立的前提**：心跳丢失的代价是"子板状态延迟一个周期"，而不是"状态永久丢失"。对模式同步（亮度、声音、掉电）这种对时延不敏感的状态，这个延迟可接受。

> 与协议层的关系：HB 在 `needAck()` 之外，**不入待 ACK 队列、不重发、不参与合并**，直接写串口。可靠传输的职责完全由本节的"周期兜底 + 变化补发"承担，协议层不掺和。

## 四、心跳载荷设计（位域压缩）

心跳载荷 3 字节（示例，实际位定义以实现为准）：

```
data[0]  运行模式：POWER_OFF / POWER_ON / WORKING / IDLE
data[1]  旋转状态：0 静止 / 1 左转 / 2 右转
data[2]  状态位（位域压缩）：
         bit0  蜂鸣器使能
         bit2  童锁状态
         bit4  供电方式（适配器/电池）
```

设计要点：

- **单帧承载多状态**：运行模式 + 旋转 + 3 个布尔状态，压进 3 字节。38400bps 下省带宽就是省时间。
- **新增状态先看位域**：布尔型状态优先塞 `data[2]` 的空 bit；枚举型才考虑扩展新字节。改位定义是**协议变更**，各板需同步，别只改主控。
- **接收侧位运算**：背板从 `data[2]` 拆童锁是 `(data[2] >> 2) & 0x03`，说明位定义可能带移位语义，拆位逻辑也属协议契约，改动要同步。

## 五、子板消费逻辑

### 显示板：跟随模式 + 开机/关机音效灯效

收到心跳后**无条件**把本地模式更新为 `data[0]`，并对模式切换做动作：

| 心跳模式 | 动作（从其他模式切过来时） |
|----------|--------------------------|
| POWER_OFF | 蜂鸣器使能则短鸣；全灭 LED |
| POWER_ON | 蜂鸣器使能则长鸣；全白灯效 1s |
| WORKING / IDLE / FACTORY_TEST | 无动作（保持当前灯效） |

- 开机长鸣+全白、关机短鸣+灭灯，都是**心跳驱动的**——显示板自己不做模式判断。
- **兜底**：显示板在 `IDLE` 状态下收到非熄屏 LED 控制命令时，自动切回 `WORKING` 并刷新 LED。应对"主控唤醒后 WORKING 心跳偶发丢失"的场景（唤醒时序见第七节）。

### 背板：运行状态副本 + 状态同步到侧滑板

- 收到心跳 → 更新本地 `g_runningState`（用于掉电判断）+ 旋转状态（同步给侧滑板驱动流水灯）+ 童锁状态。
- 背板通过单线仿真串口把心跳里的**旋转/童锁状态转发给左右侧滑板**（侧滑板不直接接入 ComProtocol）。转发有独立待发计数。

### 子板消费的共性

- **不回复 ACK**（HB 不需要 ACK）。
- **不向主控上报确认**——主控不关心子板是否收到心跳，状态收敛靠周期兜底。
- 子板行为全部由"本地副本 + 收到心跳时的动作"决定，模块之间不互相猜。

## 六、心跳驱动的电源生命周期（关键坑）

### 关机是"命令"，不是"超时判死"

背板掉电条件（主循环判断）：

```
if ((g_runningState == POWER_OFF || g_runningState == IDLE)
    && 转发给侧滑板的心跳待发数 <= 0) {
    掉电自锁释放
}
```

- 背板**只有收到关机/待机心跳**才掉电，不是"主控心跳超时没来就自己关"。
- `待发数 <= 0`：背板掉电前必须确认**转发给侧滑板的心跳都发出去了**。因为侧滑板由背板供电，背板掉电侧滑板跟着掉，必须在掉电前让侧滑板收到关机/待机状态，否则侧滑板会赖着不进入对应状态。
- 这个"掉电前等下游心跳发完"的约束，是这类**串联供电拓扑**最容易踩的坑：上游掉电会连带下游，下游的状态切换必须先于掉电完成。

### 什么场景才需要"超时判死"

这套实现**没有**用"主控心跳超时 → 判子板失联 → 降级"的机制。原因：

- 子板掉电由主控供电锁显式控制，丢失一两拍心跳不会误动作。
- 广播丢包靠周期兜底，判死会引入**误杀**（瞬时抖动、总线忙导致丢包 → 误判失联 → 误关机/降级）。

**如果子板独立供电、主控失联时子板必须自行安全处理**（如电机执行到一半需要停机），才需要"多级超时判死 + 降级"。判死阈值要显著大于心跳周期（建议 ≥ 3 个周期），且判死动作要可恢复。

## 七、唤醒时序（容易漏的状态同步）

休眠唤醒链路（非显示板按键唤醒，如传感器外部中断 / 背板 UART / RTC 定时）：

```
唤醒 → 背板/显示板重新上电 boot（子板要时间启动）
  1. 主控切回 WORKING，给子板上电
  2. 显式下发开屏命令（LED_ALL_OFF, 0）——休眠前若触发过自动息屏，
     显示板本地已处于"熄屏"态，必须显式恢复
  3. 启动 150ms 同步定时器
  4. 150ms 后：
     a. 补发一次 WORKING 心跳 —— 让刚 boot 的显示板及时切到 WORKING
     b. 失效本地 LED 状态缓存 + 强制重新下发所有状态灯
```

- **150ms 是给子板 boot 的时间**。子板重新上电期间会漏掉首包，不等它 boot 完就补发心跳，显示板还收不到。
- 不做这步的后果：显示板要等下一个周期心跳（10s）才切到 WORKING，状态灯延迟约 10 秒。
- 同步的触发源要覆盖**所有非按键唤醒路径**（EXTI / UART / RTC），漏一条路径就是一条路径的状态灯延迟。

## 八、广播不 ACK 的代价与补偿清单

| 广播包的固有弱点 | 本方案的补偿 |
|------------------|-------------|
| 丢包无感知 | 周期 10s 兜底，丢失等价于"延迟一拍" |
| 状态变化可能晚到 | 变化立即补发，即时传播 |
| 子板 boot 期间漏包 | 唤醒后 150ms 补发 WORKING 心跳 |
| 关键状态（入座/卡扣）漏上报 | 开机完成后主控主动 `STATE_QUERY` 拉一次（配合 UPDATE 状态变化上报） |
| 下游（侧滑板）收不到 | 背板转发 + 掉电前等转发队列清空 |

> 补偿总原则：**需要可靠送达的状态，改用 QUERY/UPDATE/CTRL（走 ACK）；能容忍延迟一拍的状态，留在心跳里（不 ACK）。** 别把心跳当成可靠通道用。

## 九、设计取舍与复用检查清单

这套心跳适合的场景：多子板 + 单主控 + 共享总线 + 子板行为以主控模式为准 + 子板掉电由主控控制。

新工程复用 Checklist：

- [ ] 运行模式只有一个权威（主控），子板只维护本地副本
- [ ] 心跳有周期兜底 + 变化补发，广播不 ACK 可接受
- [ ] 载荷用位域压缩布尔状态，扩展先找空 bit
- [ ] 子板掉电/降级动作由心跳命令触发，而非心跳超时
- [ ] 若串联供电：上游掉电前必须确认下游已收到关机状态
- [ ] 唤醒后留子板 boot 时间再补发心跳 + 强制刷新下游状态
- [ ] 需要可靠送达的状态不塞心跳，走 ACK 命令
- [ ] 判死（如果引入）阈值 ≥ 3 个心跳周期，且动作可恢复
