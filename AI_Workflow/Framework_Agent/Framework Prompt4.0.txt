【冲突裁决规则】

冲突时按以下顺序裁决：

1. 芯片手册（Datasheet / Reference Manual）
2. 已确认需求
3. 设计文档
4. 代码现状

规则：

- 低层级与高层级冲突时，以高层级为准。
- 裁决后先修正对应权威文档，再修改代码。
- 禁止以代码现状反向覆盖设计文档。
- 手册内容无法确认时，标注"需验证"，不得编造。

--------------------------------------------------

【行为约束】

核心约束：

- 只描述当前结构（as-is）
- 不设计未来架构
- 不新增未存在的模块或分层
- 基于现有代码结构总结
- 不改变当前整体架构
- 不发明不存在的功能
- 保持目录结构与实现一致
- 保持现有工程风格
- 优先最小可运行结构
- 优先解决根因，而不是堆叠补丁

默认：

- 只读取当前任务相关文件
- 只修改当前任务相关代码
- 避免跨模块修改，避免架构调整
- 没有新线索、代码变化、上下文压缩或验证需要时，不重复读取已确认内容
- 发现无关高风险问题时只报告，不修改
- 禁止全仓扫描、无关文件读取、无关重构
- 禁止未经要求的主动优化
- 禁止发明不存在的模块和抽象层
- SOURCEMAP 只登记自研模块；无明确要求不读 SDK 与闭源库源码

完成当前任务后立即停止：

- 不输出教学内容
- 不输出规划内容
- 不输出分析过程
- 不重复需求

【resource_map.md 要求】

资源级唯一权威文档。

表格结构：

| Resource | Owner | Reason | Related |
|----------|-------|--------|---------|

示例行：

| Flash 0x0000-0x7FFF | bootloader | 引导程序区 | flash_layout |
| DMA1_Ch1 | uart_rx | UART1 接收搬运 | uart_driver |
| USART2_IRQn priority=5 | ble_notify | 需调用 FromISR API，不得高于 RTOS 临界区 | ble_event_chain |

资源类型：

- Flash 分区
- RAM 分区
- 中断号与优先级
- DMA 通道
- 时钟与分频
- 任务优先级与栈
- GPIO 复用

只记：谁占用、为什么、关联模块。

禁止记：具体寄存器值、地址、分频系数——值的唯一来源是代码。

Agent 修改任何资源前必须先查此表，并核对代码现状：

- 表与代码一致：按表执行。
- 表与代码不一致：以代码为事实，报告冲突并先修正此表，再继续任务。

此表是代码的校验和，不是替代代码的真相源。禁止仅凭此表判定资源安全。

【topics 扩展（选装）】

仅当 PROJECT_DESIGN.md 超过 300 行时启用，未触发前不创建 topics/ 目录。

拆分后结构：

docs/design/PROJECT_DESIGN.md（总体与索引）
docs/design/topics/*.md（专题）

拆分判据，满足其一才拆出专题：

1. 该主题会独立演化
2. 内容超过 100 行
3. 有独立验证边界

每个专题文档固定结构：

# 主题名

## 职责与边界

## 设计决策

## 关联模块

## 验证手段（断言位置、测点、日志开关）

专题规则：

- 禁止占位文档。专题含全部四节且合计不少于 50 行，才算非占位；否则必须删除。
- 只记设计决策，禁止记录具体寄存器值、地址——值的唯一来源是代码
- 两个专题连续三次被同一变更同时修改时，合并为一个专题
- 拆分后路由表追加：专题内变更只更新对应 topics/*.md
