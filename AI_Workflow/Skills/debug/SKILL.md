# 硬件问题分层定位

核心纪律：**未定位根因前，禁止给出修复代码。** 先分析，后修改。
定位顺序固定：硬件 → 驱动 → 协议 → 业务，禁止跳层。

## 第 0 步：固定现象

先收集，信息不全就问，禁止直接开猜：

- 现象：可观察行为是什么（死机/数据错/无响应/复位）
- 复现率：必现 / 高频 / 偶发（偶发问题优先怀疑时序与并发）
- 复现步骤：什么输入、什么操作顺序
- 最近改动：代码、硬件、环境（温度/供电/批次）的变更
- 发生时机：上电就坏 / 运行一段时间后坏 / 特定操作后坏

## 分层排查

每层输出两类结论后才能进下一层：
**已排除项 + 证据** / **待验证项 + 具体验证方法**。
没有证据的"应该没问题"不算排除。

### 第 1 层：硬件层

- 供电：各路电压实测值 vs 额定值，纹波是否超标
- 时钟：晶振/PLL 是否起振，频率实测
- 复位：复位信号是否被意外拉低，上电时序
- 信号完整性：关键引脚波形（示波器/逻辑分析仪，写明量哪个点）
- 焊接/接触/虚焊，静电损伤

### 第 2 层：驱动层

- 寄存器实际值 vs 期望值（读回来对比，禁止假设写入成功）
- 中断：进没进（计数器/断点），优先级是否被抢占
- DMA：传输计数器、错误标志、缓冲区地址对齐
- 外设错误状态位：溢出/帧错误/CRC 错误等标志逐一查

### 第 3 层：协议层

- 抓包/日志看时序：对方发的和本机解析的是否一致
- 状态机卡在哪个状态，超时/重传路径是否走过
- 字节序、帧边界、长度字段是否解析正确

### 第 4 层：业务层

前三层全部排除后才看业务逻辑。

## 定位输出格式

- 根因：定位到 文件:行 / 寄存器 / 信号，附证据链
- 触发条件：什么时序/输入/状态下出现
- 修复建议：最小改动方案
- 回归验证：怎么确认修好了、怎么确认没引入新问题

## 禁止事项

- 禁止无证据跳层："硬件肯定没问题"不算数
- 禁止猜测性修复（改一下试试）——可以提假设，但必须标注"假设"
  并给出验证该假设的最小手段
- 禁止编造寄存器行为：未查手册的一律标「未经测试，需验证」
- 偶发问题禁止改完就宣布修好——必须给出压力/长时间验证方案
