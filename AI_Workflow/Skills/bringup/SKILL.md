# 外设驱动开发检查单

核心纪律：**硬件约束先于软件设计。** 开头必须先点明本驱动涉及的
RAM / Flash / DMA / Cache / 中断 / 时钟 / 功耗约束。

平台无关检查单：只写"要配什么、怎么验证配对了"。
**禁止编造寄存器、地址、芯片特性**——具体值一律查对应平台
参考手册（RM）/ 数据手册，查不到就标「需查手册确认」。

## 配置顺序（严格按序，每步带验证点）

### 1. 时钟

- 外设在哪个时钟域，时钟使能了吗
- 时钟频率是否满足外设要求（分频/倍频后实际值）
- 验证：读时钟寄存器实际值，或输出时钟到引脚实测

### 2. 引脚复用

- 复用功能号是否选对，与板上其他功能冲突吗
- 上下拉/驱动能力/开漏推挽配置是否符合外设要求
- 验证：对照原理图逐引脚核对，万用表量静态电平

### 3. 外设初始化

- 按手册要求的初始化顺序（有些外设顺序错了不报错但不工作）
- 工作模式/速率/数据格式与通信对端一致吗
- 验证：读回关键寄存器对比期望值；回环/自检测试（若支持）

### 4. 中断

- 优先级分组下该中断的优先级数值，会被谁抢占、能抢占谁
- 中断里干了什么：禁止阻塞、长延时、不可重入调用
- 共享变量 volatile 与临界区保护
- 验证：中断计数器确认触发；制造高频触发看是否丢中断

### 5. DMA / Cache

- DMA 通道/流分配是否与其他外设冲突，传输宽度与对齐
- **Cache 一致性**：DMA 缓冲区是否落在 Cache 区域——
  需要 Clean/Invalidate 还是放非 Cache 段，这是最高发坑点
- 缓冲区生命周期：传输完成前禁止释放/复用
- 验证：边界长度传输（1 字节、非对齐、最大长度）

### 6. 低功耗影响

- 该驱动是否阻止进睡、增加唤醒源
- 睡眠/唤醒前后外设状态需要保存恢复吗

## 输出要求

- 平台 / SDK / 工具链 / 依赖库在首次输出代码时说明
- 代码注释说明"为什么这么做"、边界条件、风险点，不解释语法
- 结尾给出**「未经测试，需验证」清单**：未查手册确认的值、
  未验证的时序假设、需要上板验证的项目

## 禁止事项

- 禁止编造寄存器/地址/芯片特性/勘误信息
- 禁止跳过验证点直接写完整驱动——每步先给验证方法
- 无把握的平台行为：降级为伪代码并说明原因
